# Standalone Mockups

Four self-contained artifacts, each proving a single idea. Unlike the numbered sets, these don't share one project — the common thread is showing the better experience and the evidence, not just describing them.

---

### `Payment_Display_Health_Dashboard.html` — "No money is missing"

On a small fraction of gateway payments, the bank captures the customer's money but the confirmation never posts back, so the account shows "$0 paid." To a client that reads as *my money is missing*, and every instance became an engineering escalation. I reframed the problem and defined the proof underneath it: a payment only counts as "display catching up" when a settlement batch exists but nothing has been credited yet — so the money is provably safe. The result is a screen-shareable dashboard with counts and dollars only, no customer data, ready-to-read talking points, a trend over time, and a by-client view — a self-serve reassurance tool that replaces an engineering escalation, backed by numbers that reconcile to a hand-verified baseline.

### `Reconcile_Payments_UX_Mockup.html` — reconcile-payments redesign

A written requirement alone leaves engineering and QA imagining different screens. This mockup ties the requirement to a concrete visual target, with a current-versus-proposed feature comparison so the reasoning behind each change is explicit — everyone builds to the same picture.

### `Meter_Reading_Screen_Mockup.html` — meter workflow, reimagined

The legacy meter-reading workflow is clunky and multi-step, and improvements described in a document rarely land. This reimagined-UX mockup puts current and proposed side by side, giving decision-makers a tangible "better" to approve or redirect before build cost is sunk.

### `Split_Bill_Enhanced_Mockup.html` — enhanced split-bill UI

Split billing is a complex scenario where the existing interface makes the operator do the mental math. This mockup surfaces the breakdown visibly, turning a fiddly edge case into an interface a user can trust at a glance.
